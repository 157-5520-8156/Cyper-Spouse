# 沈知栀机制总览

更新时间：2026-07-29

这不是一份把功能名堆在一起的清单，而是对项目中所有“让她像一个持续生活、会
受关系影响的人”的机制做的统一说明。它同时收录已经实现、迁移中的实现和明确的
后续边界，作为之后新增功能、排查旁路和设计评测的索引。

## 1. 总原则

### 1.1 目标因果链

```text
时间、生活、用户消息、平台事件、既有关系
  -> 有来源的 World Context、当前人格/Affect 与选择性 Recall
  -> PrivateTurnState
  -> 角色模型选择 now / later / silent、单条/多条及表达方式
  -> 事实/权限验收 -> 实际投递或失败
  -> 可审计的历史、记忆、期待和下一轮状态
```

角色模型拥有动机、态度、情绪表达、措辞、节奏、是否追问、是否主动、是否沉默以及
如何使用可用能力的决定权。系统向她提供有来源的事实、记忆、关系、Affect、生活处境、
能力和后果；系统仍是日历事实、投递结果和工具权限的权威，但不先生成一套“回复策略”
再让模型代写。规范边界见
[`ADR 0010`](adr/0010-controlled-high-variance-character-agency.md) 与
[`ADR 0014`](adr/0014-model-owned-private-turn-state-before-expression.md)。

### 1.2 四条不可破坏的规则

1. **先发生，后可说。** 已完成生活事件、已送达消息和已确认用户事实才可成为具体
   断言的来源；计划、模型提议和未送达文本都不是共同经历。
2. **状态必须进入角色可用的因果链。** 有意义的状态需要以来源明确的 Current Self、
   Recall 或能力/后果信息到达同一 Pinned Turn；它不能被确定性代码翻译成语气、追问、
   沉默或主动行为。
3. **行为必须能结算。** 每次延迟、主动、分段、图片或工具行动都需要取消、过期、
   成功、失败或未知这类终态，不能悬在内存里。
4. **同一事实只允许一个权威来源。** 跨 QQ、未来微信和面板共用同一 daemon/SQLite
   身份、关系、世界和事实；平台适配器只负责收发。

### 1.3 当前运行时边界

项目目前同时保留两代运行时：

| 路径 | 用途 | 当前事实地位 |
| --- | --- | --- |
| 旧行为运行时 | `MoodState`、`life_runtime`、`social_tasks`、旧记忆与日历；仅保留兼容与迁移代码 | 生产构建会持久化 world-only 写门禁，不再作为现实聊天行为源 |
| WorldKernel | 追加式世界账本、世界日程、经历、通信状态、关系/情绪投影、世界对话上下文 | 当前生产权威路径；所有状态变化必须事件化并可重建 |

因此，下文的“已实现”仅表示代码和测试中已有该机制；若标成“迁移中”，它不应被
误读为已在当前所有 QQ 对话里生效。详细迁移盘点见
[`legacy-behavior-runtime-inventory.md`](legacy-behavior-runtime-inventory.md)。

## 2. 机制分层图

```text
角色与自我核心 ─┐
用户事实与共同历史 ─┼─> 上下文编排 / 事实约束 ─> 语言与媒体表达
时间、日程、生活事件 ─┤              ^
情绪、关系、印象、边界 ─┤              |
通信注意力、未完成事务 ─┘              |
                                      投递结算
                                           |
                                   记忆、期待、生活轨迹
```

下面按“底层状态机制”“认知与事实机制”“行为节律机制”“生活与主动机制”“媒介、
平台与治理机制”展开。每一项均以输入、内部变化、外显结果和闭环说明组织。

## 3. 底层状态机制

### 3.1 人格、身份与自我核心

| 项目 | 逻辑 |
| --- | --- |
| 输入 | 角色卡、稳定身份事实、长期关系与已经确认的个人经历 |
| 状态 | 姓名、学校/城市等人物设定、气质锚点、自我核心摘要、视觉身份基准 |
| 外显 | 语言习惯、兴趣取向、拒绝方式、边界强度和可分享内容保持连续 |
| 闭环 | 角色事实不可被临场生成的台词自动改写；可沉淀的新经历先进入世界/生活账本，再被摘要读取 |

“有心理活动”不等于让模型输出一段内心独白。`PrivateTurnState` 是同轮 Proposal 的
短自由文本与来源审计，不是系统生成的回复策略，也不进入长期人格、关系或记忆。值得
长期保留的情绪、印象、承诺和记忆分别走自己的来源绑定接受链，不能从一段漂亮的解释
倒推成她早已拥有的经历或想法。

### 3.2 情绪：短期波动、基线与自然回落

**旧运行时已实现；世界模式已有可解释、可回放的事件投影。**

| 成分 | 含义 | 典型来源 | 如何进入角色判断 |
| --- | --- | --- | --- |
| 情绪基线 | 长期较稳定的心境倾向 | 已接受的长期互动与人格气质 | 作为 Current Self 的慢变量 |
| 短期 Affect | 可并存、可衰减的 emotion episode 与 PAD/core affect | 来源绑定的 Appraisal、生活结果与关系事件 | 以强度、目标、来源和时效进入 Current Self |
| 情绪残留 | 一件事过去后没有立刻消失的余味 | 已结算事件及其 appraisal | 提供跨轮连续性，不指定下一句 |
| 当前需要与边界 | 安全、精力、连接、边界等主观状态 | 角色模型看到同一 Pinned Context 后提出 | 供 `PrivateTurnState` 选择性注意 |

情绪投影可以确定性维护 episode 的半衰期、并存、归档和长期基线，但不能把高反感、
低落或亲近映射成固定语气、Reaction、回复速度、主动概率或沉默窗口。角色模型看到这些
状态后，可以形成任何有来源且不越过硬边界的当下判断。

世界模式的情绪来源不只包含用户消息。已结算的生活结果会先产生结构化
`ExperienceAppraised`，再改变情绪投影；例如 NPC 冲突可留下 irritation/guarded 余波，
目标完成可增加 joy/warmth。来源事件、强度和逻辑时间均写入账本，下一轮 deliberation
与表达提示会读取这份结果。生活描述文本本身不能靠关键词直接改情绪，避免模型写一句
“吵架了”就伪造事实。

用户文本、引用关系、附件与非文本线索作为 `InteractionEvidence` 进入模型 Appraisal；
系统不用辱骂、道歉、亲昵称呼等关键词直接写入 hurt/anger/repair 或规定可见拒绝话术。
隐私、同意、安全和法律仍是不可协商的硬边界；这些边界可以拒绝未授权 Action，但不编写
角色态度。合法 Appraisal 即使角色选择沉默或稍后回复也可独立结算。

当前世界情绪进一步分成结构化 Appraisal、带 source/target/half-life 的 emotion
episode，以及从 active episode 派生的离散向量与 PAD/core affect。它们进入 Current Self，
而 `ExpressionDraft` 由角色模型在同轮 `PrivateTurnState` 之后选择，不能从 revision
确定性编译。episode 是短中期情绪的动态权威；resolved episode 进入因果归档，不会因
投影收敛而丢失来源。正负 episode
可同时存在，最后发生的温暖不会覆盖尚未解决的受伤；NPC/目标事件造成的负面余波会限制
在较小 leakage 内，并明确保留真实 target。讽刺、潜台词、权力关系和其他语义都由看到
紧凑来源上下文的模型判断；低于置信门槛只能保留为歧义，不能写入长期伤害。

衰减、episode 半衰期、关系敏化、修复证据门槛和 spillover 上限来自版本化
`affect_profile`。具体道歉只开启观察期；纯时间流逝或重复说对不起不能完成修复，必须出现
后续一致行为证据。长期 resentment 只在多次已结算伤害后小幅延长同源负面 episode，不能
覆盖硬边界或把一次事件升级为永久判断。

平台层会保留合并前的消息 ID，并将可观测的 emoji、贴纸、附件、回复目标和消息 burst
组成有界 `InteractionEvidence`。非文本线索只调节显著性和确定度，不能单独证明强恶意。
模型结果结构或来源无效时，同一模型获得一次受约束重选；仍失败则记录技术失败并退避，
不得由本地 fallback 生成情绪、态度或可见话术。

### 3.3 关系、印象与边界

| 机制 | 输入 | 状态变化 | 对角色/系统的意义 |
| --- | --- | --- | --- |
| 关系阶段 | 持续互动与已接受的关系 Appraisal | 渐进变化并保留来源 | 进入 Current Self 和主动 cadence；不规定称呼或语气 |
| 回应印象 | 角色模型对已发生互动的来源绑定判断 | 可靠感、被接住感等慢变量 | 进入后续判断，不直接增减追发概率 |
| 尊重/安全/信任 | 已接受的关系事件与长期证据 | 累积式变化；单回合不任意改写长期关系 | 作为角色判断材料；隐私/同意权限仍由系统守住 |
| 边界与修复 | 当前 Appraisal、后续证据和未解决状态 | 可并存、衰减、修复并保留历史 | 角色决定是否表达及如何表达，系统不提供话术矩阵 |

重要约束：关系和负面情绪不是固定惩罚，也不能由“多久没回”“用了什么称呼”等局部
规则直接推出。它们需要有来源的 Appraisal 与持续证据；最终是否主动、回避、缓和或设界
仍是角色选择。

### 3.4 长期人格漂移与口吻惯性

长期人格只从有来源的累积证据缓慢漂移，不能因一次聊天或某个关键词改写。最近表达、
关系和 Affect 作为上下文保留连续性；系统不把“口吻惯性”编译成长度、提问倾向或情绪
指令，角色也不需要每轮重置为标准角色卡。

## 4. 认知、记忆与事实机制

### 4.1 五类信息及其使用权

| 信息层 | 例子 | 能否作为具体事实断言 | 写入规则 |
| --- | --- | --- | --- |
| 角色规范事实 | 沈知栀的基本身份、地点、气质 | 可以 | 人工维护或受控迁移 |
| 用户事实账本 | 用户在成都、偏好、明确说过的近况 | 可以 | 保留来源、时间、置信度和冲突键；新事实可 supersede 旧事实 |
| 已发生经历 | 已完成活动、已确认共同事件、已送达生活分享 | 可以 | 追加记录；修正以补偿事件表达 |
| 对话记录与检索记忆 | 近期聊天、主题摘要、可召回片段 | 只能辅助找话题，不可单独支撑细节断言 | 自动摘要/检索；不把模型扩写升格为事实 |
| 计划、候选与模型提议 | 明日安排、待发消息、模型猜测 | 不可以 | 仅作为未来行动或草稿；未完成前不可说成发生 |

这套分层针对的核心问题是“她自己刚编的经历，下一轮却说成是用户经历”或“明天的
计划被说成昨天做过”。检索结果必须保留说话人、时间和来源；引用前先核对 `你/她`
角色，隔夜旧话不能称为“刚刚”。

### 4.2 上下文编排器

每次生成不是把数据库和系统提示词一股脑塞给模型，而是产出一个结构化
`ContextPackage`。它应包含：

1. 当前 Observation 与近期对话；
2. 有来源的关系、边界、Affect、人格与生活状态；
3. 不能误用的旧话、说话人和时间新鲜度；
4. 有来源的相关长期事实与经历；
5. 她此刻的活动、注意力、精力和可见生活约束；
6. 当前平台能力、事实 scope 及外部 Action 的硬边界；
7. 供角色先形成 `PrivateTurnState`、必要时选择 Recall、再形成 `ExpressionDraft` 的
   精简材料，而非回复菜单或原始内部数值。

Context 不根据“在吗”、问句、情绪词或固定意图标签替角色指定注意力优先级。角色模型
结合整轮材料决定此刻注意什么、是否共情、联想到自己、追问、转题、收尾或沉默；系统只
校验 `PrivateTurnState.attended_source_refs` 没有越出同一 Pinned Turn。

### 4.3 事实约束与反幻觉门

生成前只把允许引用的事实暴露给模型；生成后再检查：

- 是否把她的话、用户的话或第三人的话混为一谈；
- 是否把计划、失败投递、未发生候选写成现实；
- 是否无来源地补完地点、人物、结果、用户经历或自己的完整往事；
- 是否把“我刚才说”误写成“你刚才说”，或把隔夜内容写成“刚刚”；

主观感受、明确假设和不构成外部事实 claim 的自然语言无需事实引用；“店里有只猫”、
人物、地点、时间、经历与结果等可被当真的陈述，无论看起来多日常，都必须来自同一
Pinned Context 的合法 source。严格性随断言的可验证性和后果提高，但不能用一堆特例
禁词硬压模型。重复、舞台表达、提问与话语风格不属于事实来源门的裁决范围；
是否使用它们由角色模型决定。结构或来源不合法时，系统只返回精确失败边界，让同一角色
模型受约束重选一次。

### 4.4 未答问题、共同线程与自我核心

角色 cognition 可基于当前 Observation 与既有来源，自由提出 ConversationThread、
Commitment 或 ResponseExpectation；系统不把问句、矛盾或“脆弱表达”自动转换成社交
任务。被接受的对象必须绑定来源、状态和到期/终结条件，不能无限续期或独立生成话术。
自我核心则是角色事实、稳定价值与已确认经历的受控摘要，不能吸收模型写出的漂亮但
无来源解释。

## 5. 通信行为与会话节律机制

### 5.1 收到消息不等于立刻回复

| 阶段 | 判断 | 可能状态 | 用户能观察到的效果 |
| --- | --- | --- | --- |
| 入站去重与合并 | 是否是网关重投、是否连续发送同一件事 | 合并中的一轮输入 | 多条短消息不会机械地逐条抢答 |
| 可达性与考虑机会 | 已提交活动、手机距离、平台连接和通知到达 | 未观察、Observation 已提交、考虑到期 | 真实不可达可以延后模型调用，但消息语义不直接决定回复 |
| 角色认知与表达 | Observation、Current Self、Recall、能力与硬边界 | 角色选择 `now / later / silent` 和 Beats | 没有关键词或情绪—表达矩阵替她作决定 |
| 延迟 Action | 角色已接受的 `later` | 稳定身份、来源、到期、过期和终态 | 重启后 effect-once 恢复；新 Observation 终结未授权旧认知 |
| 投递 | 实际平台发送成功与否 | delivered / failed / unknown 等终态 | 只有成功的文字会进入共同聊天史 |

只有合法 `ExpressionDraft` 的 `later` 或 `silent` 才能表示角色决定暂不回复。未提交
Observation、模型超时、解析失败、来源拒绝和 worker 崩溃都是技术状态，必须进入可观察
恢复，不能被解释成“已读不回”。新的 Observation 会让角色基于更新后的完整情境重新判断。

会话可依据真实入站/出站时间维护 cold / warm / hot 的运输节律，用来设置有上限的 burst
合并窗口；它不能根据短句、长篇、情绪、边界或“需要想想”等语义标签选择是否回复。
逻辑世界时间不参与热度计算，防止时间跳跃把陈旧会话误判为正在热聊。

### 5.2 用户连续输入与长篇叙述

合并器只依据平台消息 ID、到达时间、burst 边界和有上限的静默窗口组织 Observation，
不解析“长篇开头”“嗯”“晚安”、问题或情绪来裁定用户是否说完。合并后的原消息顺序、
附件与回复目标完整进入 Pinned Turn；角色模型结合上下文决定现在回答、等待、沉默还是
采用多 Beat。每个已提交 Observation 都必须拥有可恢复的 expression lifecycle，不能因
合并器一直猜测“可能还有下文”而永久失声。

### 5.3 打字、分段与用户打断

角色可在一个 `ExpressionDraft` 中选择一个或多个 Beats，并为 Beat 提供可执行的 cadence。
平台执行层在消息间保留真实插话窗口；用户新消息始终成为新的 Observation，而不是先被
本地规则分成“附和/补充/打断”。尚未越过 Action 授权边界的旧 cognition 由新 Observation
原子终结；已经授权或正在投递的 Beat 只能通过显式 Action 状态、取消能力和 effect-once
规则结算，不能静默丢弃或重复发送。角色在新回合决定是否继续原话、改口或转向。

### 5.4 读后延迟、情绪性沉默与补回

Affect、活动、关系和时间跨度进入 Current Self，角色据此自由选择 `now / later / silent`
及表达内容。系统不把温暖映射成快回，也不把低落、生气或被冒犯映射成慢回、短句或沉默。
若角色选择 `later`，到期后仍由角色已接受的 Action 执行；若先前只是技术失败，系统按
可靠性生命周期重试，不能机械补发“刚刚在忙”等本地话术。

### 5.5 会话余韵与发散聊天

余韵不是独立的固定触发器、双发模板或追问旁路。同一轮是否有补充、发几条、使用哪种
模态，由角色模型在一个带合法 `PrivateTurnState` 的 `ExpressionDraft` 中选择；真正稍后
才形成的表达复用事件驱动主动考虑。系统只把已接受的 `later` 或多 Beat 选择编译成可恢复、
可打断且 effect-once 的 Action；新 Observation 会终结尚未越过授权边界的旧认知，但不会
靠本地规则另写一句余韵。

### 5.6 重复、AI 味与对话自然度

系统不设置问题数量预算、重复问句 sanitizer、助手腔禁句、固定“先接住”顺序或
情绪—表达矩阵。这些都会越权替角色决定语言行为。自然度来自同轮因果链：紧凑的当前
人格/Affect/近期自身经历进入 Context，角色先形成 `PrivateTurnState`，按需选择性 Recall，
再自行选择共情、自我分享、追问、转题、沉默或其他未枚举表达。确定性验收仅覆盖结构、
事实来源、隐私与同意、安全、能力与 Action 权限、effect-once 和回执。

当出现“好奇宝宝”、自问自答、过度客套、无来源熟人故事或机械连发时，应检查
Current Self/Recall 是否真的到达模型、`PrivateTurnState` 是否先于表达形成，以及投递
是否按接受的 Beats 执行；不能用问号配额、关键词删句或模板改写掩盖因果链缺口。

## 6. 生活运行时、日历与真实连续性

### 6.1 生活运行时

生活运行时模拟的是**可以影响沟通的当前处境**，不是为了聊天而编流水账。它包括：

- 当前活动与地点层级：休息、学习、吃饭、和同学、出门、睡眠等；
- 精力、可中断性、手机距离、通知注意力、已读/打字状态；
- 由来源绑定 Appraisal 接受的用户互动余波；其语义由模型提出，不用“低落/冒犯/道歉”
  关键词写入预设后果；
- 慢性状态与已发生事件，为后续生活发展模型提供连续约束，但不直接增减某类社交行为；
- 由生活发展模型基于当前世界自由提出的非日常事件、人物和长期方向；系统只校验时间、
  来源、权限、因果与可重放性，不用固定日期剧本选择内容。

时间只提供当前约束和世界背景，不提供活动模板，也不能直接断言“下午三点所以她一定
在上课”。生活发展模型基于完整世界提出计划或事件；运行时账本只把已接受、已推进的
活动记录为事实，活动完成后才可能生成私有经历和可分享素材。

### 6.2 日计划、周计划与日历账本

| 层级 | 内容 | 关键规则 |
| --- | --- | --- |
| 日计划 | 当天的私有活动候选、起止时段、活动推进 | 计划不是记忆，未到时间不能说已经做过 |
| 周计划 | 本周主题、约会/出行、跨日旅行、创作或重要安排 | 每周少量命名事件；例行时段只是背景，避免碎片化轮询 |
| 日历事件 | planned / active / completed / cancelled，含调整原因 | 取消和变更保留原因；已完成经历不被重写 |
| 已发生经历 | 完成活动、生活结果、可沉淀的记忆 | 只有它可回答“上周三做了什么” |

时间问答必须区分未来与过去：“明天准备做什么”读取计划且表明可变；“昨天/上周三
做了什么”只读取已完成经历；没有记录就承认不确定，不能为日历好看而倒编故事。

### 6.3 生活分享、期待回应与用户反作用

一个生活事件有四个阶段：发生、成为私有经历、角色选择是否分享、真实送达。只有在角色
Proposal 中明确建立且通过来源验收的 ResponseExpectation 才进入等待投影；用户后续回应
由同轮 cognition 结合原 expectation 评估，不能用回复时长或温度标签自动改变安全感、
主动意愿或下一次表达。

反过来，用户互动可以成为未来生活发展的来源。生活模型可据此提出与角色当前活动、
关系和 Affect 一致的新计划或事件，系统校验因果引用；不能用“脆弱就多看手机”“争执就
降低负荷”等固定映射，更不能改写当前或过去活动来迎合台词。

### 6.4 “先生成还是灵光一现”的边界

大事件（旅行、约人、跨日安排、重要经历）应先写入计划或发生账本，再谈及。小观察
可以在当前已发生环境中自然浮现，例如已确认去过书店后才想起书架上的一个细节；它也
应带来源、范围和低权重，不能立刻升级成完整的可反复引用往事。没有发生依据时，宁可
只表达泛化感受，也不要制造可污染长期记忆的具体事件。

## 7. 主动性、等待与社交事务机制

### 7.1 主动消息不是定时骚扰

生活、Affect、关系、Thread、Commitment 与 ambient cadence 只打开主动考虑机会。到期时
角色模型看到完整 Pinned Context，自由形成未枚举的 `impulse_summary`，再选择
`now / later / silent`；系统不预建分享、好奇、安慰、庆祝、想念或任何其他动机候选。

睡眠、高专注、深夜、边界与未回应历史可以改变考虑机会的随机权重并进入 Context，但
不能在模型调用前替角色 `hold`。预算、平台能力、隐私、同意和安全可以阻止未授权的外部
Action；角色选择的 `silent` 只终结本次 consideration，之后仍按正常情境节奏再考虑。

### 7.2 等待回应与不满的渐进曲线

等待时长、原消息、关系、生活和已接受的 expectation 以来源绑定的形式进入 Current Self。
角色模型决定它意味着普通等待、困惑、失落、无所谓、想追问或任何其他反应；系统不按
短/中/长时间映射情绪、追问概率、语言温度或日程。

平台级速率、预算和未回应外发上限仍是防止未授权刷屏的外部效果边界。它们可拒绝或延后
Action，但不能伪造“她不想发”的语义，也不能替角色选择下一条内容。

### 7.3 社交事务的生命周期

生产路径不按关心、余韵、追问等语义任务类型生成旁路。角色已选择的 `later` Action、
主动 consideration 与 expression reliability lifecycle 分别拥有稳定
身份、来源、到期、过期、claim、attempt 和终态。新 Observation 原子终结尚未越过
Action 授权边界的旧 cognition；真正成功投递才进入共同历史。发送失败按同一 Action 的
回执语义结算，不重新生成或盲目重发旧文本。

## 8. 多模态、自拍与视觉身份机制

### 8.1 用户图片、表情和反应

用户图片先记录附件元信息；配置视觉模型且预算允许时，再产生只描述可见内容、绑定附件
来源的分析。角色模型决定是否注意该结果，以及选择 Reaction、Sticker、文字、图片或
沉默；NapCat/OneBot 只执行已接受的 Action，不默认“先反应再说话”。一张照片也不能在
没有相应权限与证据时证明人物身份。

### 8.2 表情包、找图与生成图

当前能力以已有贴纸、图像理解和可选生成/渲染为主。能力清单、预算、关系/同意权限、
版权与安全是模型可见的硬边界；在边界内是否使用媒体及其内容由角色选择，不由关系阶段
或情绪矩阵自动触发。外部图片搜索结果也不能当作角色记忆。

### 8.3 自拍的主体性与一致性

自拍不是用户一句要求就必须答应的工具。角色可基于完整情境选择发送、拒绝、转移、
以后再说或沉默；系统不按关系阶段、语气或情绪替她选择。预算、同意、隐私、安全、
视觉事实与平台能力仍是不可绕过的硬边界，主动自拍中的生活 claim 必须来自已发生经历。

视觉一致性目前只有 visual bible/参考集和提示词锚点，**尚未完成 LoRA 或 FaceID
训练**。训练前需要可授权且一致的数据集、人物基准、远端 GPU、评测图集、隐私/内容
边界与成本控制；不能把“生成过几张好看图”误当成角色一致性已经解决。

### 8.4 小屋面板

像素小屋是 daemon 已有状态的只读投影：活动、手机注意力、情绪和挂起事务映射成
`scene_id/location/action/expression/time_of_day`。它不能反写生活事实，也不能把计划表演
成已经发生。当前小屋的实体家具、遮挡、碰撞、多场景和动作库是独立的视觉工程，
记录在 [`visual-home-roadmap.md`](visual-home-roadmap.md)，不应挤占闭环与对话质量工作。

## 9. 平台、共享身份与投递机制

### 9.1 多平台共享

QQ 官方机器人、NapCat QQ 小号、未来微信都应通过同一账号映射进入同一用户实体，因此
共享：聊天历史、用户事实、关系、情绪投影、生活日历、社交事务和未完成线程。平台不同
只影响可用媒体、真实回执、风控、主动发送能力和消息格式，不应创建第二个“沈知栀”。

当前主通道是 NapCat QQ 小号；QQ 官方机器人保留为可选通道；微信尚未接入。测试同一
会话时应只启用一个 QQ 出站通道，避免双重回复。

### 9.2 可靠投递

出站消息先被计划为 outbox/Action，再由适配器投递。只有成功才写入可见聊天史并允许
产生来源绑定的送达后果；失败保留失败记录、允许重新决策；适配器调用后进程中断且无平台回执时标为
`unknown`，不得盲目重发。这个规则是避免“她以为已经说过，但用户其实没收到”的基础。

## 10. 工具、隐私、成本与安全机制

### 10.1 MCP 与电脑操作

工具调用是受控提案，不是角色可直接执行的幻觉能力。涉及账号、文件、电脑操作、对外
发送或第三方修改时，必须等待用户明确确认；工具结果、失败和副作用都应被记录，并只
把必要结论用于后续对话。角色不能声称已经替用户完成未确认的现实操作。

### 10.2 成本闸门

聊天模型、视觉理解、语音、图片生成和主动媒体均受日/月预算、类别上限、缓存复用和
显式能力开关控制。这些边界只说明当前有哪些 Action 可用；不能用“真正需要”、关系或
情绪的本地判定替角色选择能力。同一附件可以复用有来源的分析，图片生成默认能力开关及
目标预算见
[`cost-control.md`](cost-control.md)。

每次 provider 调用按 purpose 记录模型、成功状态、延迟、prompt/completion/reasoning
tokens 及 cache hit/miss tokens。主、备 provider 都失败时记录技术失败并按配置退避；
不得使用本地确定性 fallback 生成情绪、态度、沉默结论或可见话术。若部署独立恢复角色
模型，必须显式配置、默认关闭、读取同一 Pinned Context，并通过完整来源与 Action 验收。

### 10.3 内容与关系安全

系统不应承诺“她绝对自主”或把程序状态伪装成可验证的人类意识。更合适的表达是承认
角色设定会影响表达，同时保留她能拒绝、能不高兴、能慢热的行为边界。任何 NSFW、
身份、图片或现实操作能力都仍受模型、平台与本地安全策略限制。

## 11. 可观察性、评测与故障定位

### 11.1 面板与审计

daemon 面板应显示可读审计而非暴露完整系统提示词或私有摘要：当前活动、Current Self
来源、Recall 命中、consideration/expression lifecycle、投递状态和工具提案。调试视图
展示 provider 实际可见的 source scope、能力与硬边界，不能把本地推断的“表达策略”伪装
成角色决定。

### 11.2 必备评测维度

| 维度 | 必须验证的问题 |
| --- | --- |
| 事实与说话人 | 会不会把她编的事归给用户、把计划说成发生、把隔夜说成刚刚 |
| 情绪与关系 | 来源绑定的 Appraisal/Affect/关系变化能否进入后续 Current Self，且没有关键词行为矩阵 |
| 消息节律 | 连续输入、长篇、已读延迟、分段、用户打断、重启恢复是否一致 |
| 主动行为 | 情境/ambient 机会是否到达角色模型，`now/later/silent` 是否 effect-once 且无动机旁路 |
| 时间与日历 | 过去只读经历、未来只读计划，取消/变更不改写历史 |
| 平台一致性 | 官方 QQ、NapCat、未来微信是否走同一回合、事实和投递结算 |
| 成本与安全 | 无视觉配置、预算耗尽、工具未确认、投递失败时是否安全降级 |

除了单元测试，需要持续维护多轮对话回放集和时间旅行测试。真人感问题要先还原事件链：
输入、当时生活、决策、状态差异、上下文、模型原文、清洗结果、投递结果；再判断是
模型、编排、事实、状态、适配器还是显示层的问题。

## 12. 机制接入检查单

以后新增任何“更像人”的需求，例如新的情绪、一个主动行为、一个生活场景、一种媒体
或一个平台，先回答：

1. 事件源是什么，可靠性如何，谁拥有这条事实？
2. 它是瞬时、活动、对话余波、慢性轨迹还是长期事实？
3. 它怎样开始、持续、衰减、升级、修复和取消？
4. 它怎样以来源明确的事实、Current Self、Recall、机会、能力或后果到达角色，而不先替
   角色选行为？
5. 成功、失败、重启、换平台和模型幻觉时，如何不产生假历史或重复动作？
6. 哪些是角色决定，哪些是事实/隐私/安全/权限/回执硬边界？是否存在既非硬边界、又替
   角色选择语义行为的代码？
7. 哪个确定性测试或回放样本能证明它真的参与了闭环？

若一个功能只能回答“给 prompt 多加一句”，它还不算完成；若它无法解释自己为什么
发生、为何没发生、后来怎样结束，也不应进入长期运行时。

## 13. 已明确但未完成的方向

- 继续删除旧运行时的生产写入口，并以冷重放和通道测试证明 World V2 是唯一事实权威；
- 持续验证情境/ambient consideration、Expression lifecycle、Expectation assessment 与
  跨平台恢复的事件身份、重放和 effect-once；
- 以有版权/授权的数据集建立稳定的视觉身份训练与自拍评测，而非只靠临场提示词；
- 接入微信时复用同一身份/世界/投递结算，不复制状态机；
- 持续完善多周时间旅行、真实聊天回放和模型 A/B 评测，区分模型能力不足与系统旁路；
- 将小屋的实体化、多场景、碰撞和动作库作为独立视觉路线推进，继续保持它只读世界状态。
