# World V2 重大生平迁移缺口

状态：主观方向与客观迁移已分权实现；通用坐标 head、原子结算和冷重放已闭合；无剧情类型枚举。

## 问题

World V2 已能让 World Author 提出开放的生活机会或外界偶然性，并让 Character
Model 对属于自己的行动作出 `accept / no_op` 选择，形成 Plan、Occurrence、
Experience 和可持续一段时间的 Dynamic Life Arc。现有 Dynamic Life Arc 主要为
世界提供长期叙事语境、标签以及有限的地点、人物和活动可能性，不能可靠改写角色
的基础生平坐标。

因此，角色可能在具体情境中自由形成实习、筹备某项事业或搬家的想法，也可能完全
不产生这些想法、只短暂想过、忘掉、反悔或走向未被本文举例的方向。本文使用的
“创业”“退学”“毕业”“就业”“迁居”都只是检验状态边界的例子，不是可枚举的事件
类型、提供给模型的选项、预设目标或人生阶段。实现边界是：World Author 可在一个
候选结果内声明由该结果本身建立的客观坐标变化，独立来源审查核对二者的语义闭包；
Character Model 可另行自由形成只属于 `direction.*` 的主观长期方向或选择不形成。
两者与结果、审计、接受在同一 CAS 提交中落账。所有生活上下文消费者
读取同一个坐标 head；旧 head 留在不可变事件历史中，不会因定时 Arc 结束而复活。

## 权责边界

- Character Model 决定角色自己的动机、是否行动、行动意图、可选时间以及参与者；
  系统不得把用户提到某家店直接映射成“她会去”，也不得替她决定创业。
- World Author 提出角色不能自行决定的外界机会、阻力、偶然性和候选客观结果；它
  不决定角色的欲望或选择。
- 只有经授权并完成结算的后果，才可能成为重大生平迁移的依据。模型的想法、计划、
  对话措辞或未结算事件都不能直接改写基础生平。
- 确定性系统只负责来源闭包、状态迁移权限、冲突检查、effect-once、CAS、回放和
  补偿，不把某种人生选择硬编码成角色应该做的事。
- Major Biographical Transition 不是剧情产生器。它只接纳已经由开放选择与外界
  结算形成的状态变化，不能向模型暴露“创业/就业/退学”等有限菜单，也不能因为
  年龄、日期、分数或累计事件达到阈值便自动安排人生。

## 用于检验边界的两个情境探针

以下情境只用于暴露能力缺口，不是生产剧情条目、模板、候选库或必经流程。实现必须
同样允许它们从未发生，并容纳本文没有列举的其他想法与人生方向。

### 小事件：因聊天惦记一家店，后来决定去吃

1. 用户提到店铺的 Observation 可以形成来源明确的 Life Influence 或记忆线索，
   但不证明角色去过。
2. 后续生活 deliberation 中，角色可能自行发起记忆召回，再自由决定忽略、继续
   惦记、形成到访 Plan 或产生其他想法；系统不能确保她一定想起或行动。
3. 任意新店可由 World Author 在候选结果内以 `provisional_places` 提出；只有被选中
   的结果完成结算后，才受控物化为可复用、带时区与隐私的 `attempt_only` 地点能力。
   该能力不证明营业、到场、进入或访问成功。
4. 只有到访 Plan 真正执行并结算后，才形成 Experience，并可影响情绪、关系、
   记忆、媒体或之后的选择。

### 大事件：角色在某次自由 deliberation 中产生创业想法

1. 系统不生成“创业”候选。Character Model 可能结合当时的生活、情绪、记忆、
   关系和资源自行形成这个想法，也可能形成完全不同的想法或没有长期想法。
2. 她是否继续想、是否尝试、怎样尝试和何时放弃属于 Character Model；市场、
   合作者反应、资金结果和突发阻力属于 World Author、外部观察或后续结算。
3. 一次念头不自动产生 Plan，“开始筹备”也不等于已经成为创业者。想法可以消退、
   反复、转向或在没有显著结果的情况下结束。
4. 后续开放事件的客观候选若本身会改变基础身份，可携带通用的 objective
   biographical coordinate replacement；只有该候选真正被结算才生效。角色对此形成的
   “我想继续试”或“我想停下”属于独立 `direction.*` 坐标，不能凭主观选择伪造已经
   就业、毕业或迁居。两个模型都自由给出 namespaced 状态值，系统不接收创业/就业/
   退学等事件类型菜单。投影原子消除冲突旧值，不存在预设里程碑清单、固定阶段顺序
   或“创业成功”目标。
5. 失败、暂停、转向或退出若确实发生，通过各自的结算后果形成同一坐标的下一 revision，不能
   改写历史，也不能被系统为了剧情完整性强行生成。

## 已实现的通用机制

- World Author 的候选只含客观结果，并可声明由该结果本身建立的开放客观坐标变化；
  不含人生方向、动机或供角色勾选的未来菜单。
- Character Model 在 pinned Context 中同时选择客观结果并自由输出一个可选
  主观 `direction.*` replacement；`null` 表示此次没有形成长期方向。
- 活跃 aspiration 只作为来源明确的内心材料进入开放 deliberation；旧的
  `crystallizes_into → future_opening` 生产触发已退役。角色接受一个开放 Plan 时，可用
  精确的 planting event ref 表明“这次安排把这个念头具体化了”，Plan 与
  `AspirationCrystallized` 同一 CAS 批次提交；不绑定则愿望继续存在或以后淡出。
- 独立来源审查核对客观迁移是否由精确候选分支建立；系统同时校验 namespaced 当前值、
  被替换前缀、主客观命名空间隔离、受保护命名空间以及学业—校历的结构闭包。
- 模型结果审计、Outcome Proposal、Acceptance、Settlement 与新坐标 head 同批提交；
  冷重放从 settlement 原样重建。
- 同一 coordinate 的后续迁移增加 revision 并替换 head，历史事件不改写；不同 identity
  不能抢占已经由另一 coordinate 管理的前缀。
- 当前 coordinate 的稳定 identity、revision、隐私和 settlement ref 会进入能力清单；
  后续候选若覆盖相同 namespace 必须复用原 coordinate ref。普通表达只能从允许披露的
  coordinate 派生精确 claim capability，`private/withhold` 不会因压缩而降级。

坐标替换不会机械删除独立存在的 Plan、Resource、Location 或 NPC。一个人毕业、搬家或
改变工作，并不自动证明某段关系、某项财物或每个既有约定都终止；这些实体若确实变化，
仍需各自有来源的授权事件。事件机的 reviewed 地点与生活 opening 会读取统一的当前
biography head，因此冲突的基础场景不再获得新机会，但已存在的独立事实不会被标签替换
偷偷抹除。

## 后续扩展仍须回答

- 哪些基础坐标属于可迁移生平，哪些只属于 Life Arc、Plan 或普通 Experience？
- 一个新地点、新职业、新组织或新 NPC 如何从 Proposal 中获得长期、可撤销的能力？
- 迁移如何原子重配校历、日程、资源、住所、关系和事件空间，并避免半迁移状态？
- 如何判断开放事件链的已结算后果足以授权迁移，而不建立里程碑目录、阈值脚本或
  预设人生路线？
- 冷重放、并发 CAS、失败恢复和补偿后，基础生平与所有下游投影如何保持一致？

## 验收方向

- 同一句“那家店不错”可以被角色忽略、记住、稍后想起或据此计划，选择由角色模型
  作出；系统只验证事实和能力边界。
- 无论角色是否产生创业想法，系统都不得向她提供创业选项或为了测试而推动该路线；
  若她偶然产生并继续该想法，后续发展仍由新的自由选择与外界结算共同形成，可以
  中断、淡出、转向或没有结果。
- 除本文示例外，角色自由形成的其他长期方向必须能经过同一通用机制，新增方向不应
  要求开发者先把它加入类型枚举或剧情库。
- 完成退学、毕业、就业、自雇或迁居后，世界不再同时保留冲突的旧基础身份；对话、
  日历、地点、NPC、媒体和生活事件均读取同一迁移后的世界事实。
